# Milestone 1.1 — Playable board

## Outcome

Ready for milestone closure after T-003 publication and issue closure. Geometry, immutable commands, document-local session composition and the shared Canvas/control view demonstrate a manually controlled tetromino board. Gravity/scoring are explicitly later milestone scope; this is not a complete phase or release.

## Code review

Reviewed src/core/geometry.ts, src/core/game.ts, src/app/session.ts, src/ui/board.ts, src/ui/app.ts, src/entry/web.ts, styling, Vite/Playwright configuration and tests. Geometry owns all cell/bounds rules; UI draws snapshots without collision logic. Session draws one independent uniform next type on start and consumes no stream on render. Rejected moves/spawns preserve settled state; input is attached only to the focused board. No platform persistence or duplicate game engine is introduced. Checked normal-piece palette, centered layout and semantic controls. No unresolved contract violation was found within this milestone.

## Browser environment and recovery

Node 24.22.1, Playwright 1.62.1, Chromium shell 151.0.7922.34 revision 1234 and managed Firefox 153.0 revision 1538. One absolute project-owned .browser-cache root is used by installation/probes and scripts/browser.mjs. No personal/system browsers or profiles were used.

The default CDN returned HTTP 200 text/html, 195 bytes, beginning with an HTML Site Unavailable page rather than a ZIP; this independently affected Chromium and Firefox. The official PRSS Firefox fallback supplied a valid 113412908-byte ZIP and Firefox installed. The installer then failed while refreshing its own cache lock during FFmpeg setup; no concurrent install was active. Required Chromium/FFmpeg assets were recovered from the version-matched official image using selective safe extraction, not repeated bad downloads.

Official image: mcr.microsoft.com/playwright:v1.62.1-noble, Linux amd64 manifest sha256:c091b21d9fae78c76e85cd4356431e9b018402f172a214fc7d7a5e9a7e29d8ac. The manifest/config digests were verified. History identifies the Chromium installation layer: sha256:4d796d6a81781a9c3c9bbaa6e641a37b96cab44f1854681bb160a619373e1697, 296229610 compressed bytes; both size and SHA-256 verified before extraction. Extracted only chromium-1234, chromium_headless_shell-1234 and ffmpeg-1011 beneath ms-playwright, rejecting traversal, external links and device entries and preserving executable modes. Later image history installs only Firefox/WebKit; no selected Chromium replacement is indicated. No global browser or host dependency was installed.

Firefox initially launched but failed page creation with content-process uid_map EPERM errors. The repository-policy documented MOZ_DISABLE_CONTENT_SANDBOX=1 process-only override passed two isolated local input/Canvas/page/teardown cycles. Chromium shell passed the same two-cycle probe normally. Config enables that Firefox override only when TETRIS_FIREFOX_SANDBOX_OVERRIDE=1 is explicitly set for trusted local tests; it is not a production or global default. The application tests used that flag on this host. This reduced browser content isolation is a stated test-environment limitation; the host sandbox remains unchanged.

## Follow-up — Private development file routes

A synthetic .tkn fixture showed that ignoring credentials in Git does not prevent Vite from serving them: the direct route returned HTTP 200. Added explicit fs.deny coverage for .tkn files while retaining Vite’s environment/certificate/Git defaults. The HEAD-only regression now receives 403 for direct, percent-encoded, raw-query and @fs paths. The fixture is created exclusively, contains no credential and is removed after the owned dev server exits. No real token was requested through HTTP or printed. This repair changes only development hosting, not gameplay or completed task boundaries.
